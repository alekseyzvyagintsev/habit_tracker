# API Документация для Habit Tracker

Данный документ описывает REST API для приложения Habit Tracker, позволяющего управлять полезными привычками и пользователями.

---

## Базовый URL

```
http://localhost:8000
```

или в production:

```
https://your-domain.com
```

---

## Аутентификация

API поддерживает аутентификацию через JWT-токены (Django REST Framework Simple JWT).

### Доступные эндпоинты для аутентификации:

- `POST /login/` — получение пары токенов (access и refresh)
- `POST /token/refresh/` — обновление access-токена
- `POST /token/verify/` — проверка валидности access-токена

После входа используйте `access` токен в заголовке:

```
Authorization: Bearer <access_token>
```

## Пользователи (`/users/`)

### 1. Регистрация пользователя

- **Метод:** `POST`
- **URL:** `/register/`
- **Описание:** Создаёт нового пользователя. Доступно всем.
- **Права доступа:** `AllowAny`

#### Тело запроса:

```json
{
  "email": "user@example.com",
  "password": "password123"
}
```

#### Ответ (успех):

```json
{
  "id": 3,
  "email": "user@example.com"
}
```

---

### 2. Получение списка пользователей

- **Метод:** `GET`
- **URL:** `/users/`
- **Описание:** Возвращает список всех пользователей. Доступно только администраторам.
- **Права доступа:** `IsAuthenticated`, `IsAdminUser`

#### Ответ:

```json
{
  "count": 3,
  "next": null,
  "previous": null,
  "results": [
    {
      "id": 1,
      "email": "admin@example.com",
      "phone_number": null,
      "avatar": null,
      "country": null,
      "is_active": true
    },
        {
      "id": 2,
      "email": "moder@example.com",
      "phone_number": null,
      "avatar": null,
      "country": null,
      "is_active": true
    },    {
      "id": 3,
      "email": "user@example.com",
      "phone_number": null,
      "avatar": null,
      "country": null,
      "is_active": true
    }
  ]
}
```

---

### 3. Получение профиля пользователя

- **Метод:** `GET`
- **URL:** `/users/<int:pk>/`
- **Описание:** Возвращает профиль пользователя. Владелец видит все поля, другие — только публичные.
- **Права доступа:** `IsAuthenticated`, `IsUserOwner` или `IsAdminUser`

#### Ответ (для владельца):

```json
{
  "id": 3,
  "email": "user@example.com",
  "phone_number": "+79991234567",
  "avatar": "/media/avatars/user.jpg",
  "country": "Россия",
  "is_active": true
}
```

#### Ответ (для стороннего пользователя):

```json
{
  "id": 3,
  "email": "user@example.com"
}
```

---

### 4. Обновление профиля

- **Метод:** `PUT` / `PATCH`
- **URL:** `/users/<int:pk>/`
- **Описание:** Полное или частичное обновление профиля. Доступно владельцу или администратору.
- **Права доступа:** `IsAuthenticated`, `IsUserOwner` или `IsAdminUser`

#### Тело запроса (пример):

```json
{
  "phone_number": "+79991234567",
  "country": "Россия"
}
```

#### Ответ:

Возвращается обновлённый объект.

---

### 5. Удаление пользователя

- **Метод:** `DELETE`
- **URL:** `/users/<int:pk>/`
- **Описание:** Удаляет пользователя. Доступно владельцу или администратору.
- **Права доступа:** `IsAuthenticated`, `IsUserOwner` или `IsAdminUser`

#### Ответ:

- `204 No Content` — при успехе.

## Привычки (`/habit/`)

### 1. Создание привычки

- **Метод:** `POST`
- **URL:** `/habit/create/`
- **Описание:** Создаёт новую привычку. Привязывается к текущему пользователю.
- **Права доступа:** Только авторизованные.

#### Тело запроса:

```json
{
  "action": "Прочитать 10 страниц книги",
  "date_start": "2026-04-08T08:00:00Z",
  "date_end": "P30D",
  "location": "Дома",
  "periodicity_days": "P1D",
  "time_to_complete": "PT120S",
  "is_pleasant": false,
  "is_public": true
}
```

#### Поля:

| Поле               | Тип      | Обязательн. | Описание                                                               |
|--------------------|----------|-------------|------------------------------------------------------------------------|
| `action`           | string   | Да          | Описание действия                                                      |
| `date_start`       | datetime | Да          | Дата и время начала выполнения (ISO 8601)                              |
| `date_end`         | duration | Нет         | Продолжительность действия (дельта от `date_start` по умолчанию 30 дн. |
| `location`         | string   | Да          | Место выполнения                                                       |
| `periodicity_days` | duration | Да          | Периодичность (ISO 8601 duration, от 1 до 7 дней)                      |
| `time_to_complete` | duration | Да          | Время на выполнение (ISO 8601 duration, до 120 секунд)                 |
| `is_pleasant`      | boolean  | Нет         | Приятная ли привычка                                                   |
| `is_public`        | boolean  | Нет         | Публичная ли привычка                                                  |
| `reward`           | string   | Условно     | Вознаграждение (не может быть с `related_habit`)                       |
| `related_habit`    | int (ID) | Условно     | ID связанной привычки (должна быть приятной, не может быть с `reward`) |

> Примечание: Поле `owner` устанавливается автоматически. `is_active=True` по умолчанию.

#### Ответ (успех):

```json
{
  "id": 1,
  "action": "Послушать любимую песню",
  "created_at": "2026-01-29T21:44:00.895304+03:00",
  "last_notified_at": "2026-02-24T20:37:30.714179+03:00",
  "date_start": "2026-01-29T21:44:00.895065+03:00",
  "date_end": "30 00:00:00",
  "location": "везде",
  "periodicity_days": "1 00:00:00",
  "reward": null,
  "time_to_complete": "00:02:00",
  "is_pleasant": true,
  "is_public": true,
  "is_active": true,
  "owner": 1,
  "related_habit": null
}
```

---

### 2. Получение привычки по ID

- **Метод:** `GET`
- **URL:** `/habit/<int:pk>/`
- **Описание:** Возвращает детали привычки. Доступно владельцу.
- **Права доступа:** Только владелец.

#### Ответ:

Возвращается объект привычки в формате JSON.

---

### 3. Обновление привычки

- **Метод:** `PUT` / `PATCH`
- **URL:** `/habit/<int:pk>/update/`
- **Описание:** Полное или частичное обновление. Доступно владельцу.
- **Права доступа:** Только владелец.

#### Ответ:

Возвращается обновлённый объект.

---

### 4. Удаление привычки

- **Метод:** `DELETE`
- **URL:** `/habit/<int:pk>/delete/`
- **Описание:** Удаляет привычку. Доступно владельцу.
- **Права доступа:** Только владелец.

#### Ответ:

- `204 No Content` — при успехе.

---

### 5. Получение списка привычек

- **Метод:** `GET`
- **URL:** `/habit/list/`
- **Описание:** Возвращает список привычек. Владелец видит свои и публичные, другие — только публичные.
- **Права доступа:** Только авторизованные.
- **Пагинация:** Включена.

---

## Валидация

Система проверяет логические ограничения:

- ❌ Нельзя указать `reward` и `related_habit` одновременно.
- ❌ У приятной привычки не может быть `reward` или `related_habit`.
- ❌ `related_habit` должна быть приятной.
- ❌ `time_to_complete` > 120 секунд.
- ❌ `periodicity_days` > 7 дней.

---

## Ошибки

- `400 Bad Request` — ошибка валидации или некорректные данные.
- `401 Unauthorized` — пользователь не авторизован.
- `403 Forbidden` — доступ запрещён.
- `404 Not Found` — объект не найден.

---

## Примечания

- Время передаётся в формате ISO 8601.
- Длительности — в формате ISO 8601 Duration (например, `P1D`, `PT30S`).
- Все эндпоинты защищены от анонимного доступа, кроме регистрации и входа.
- Публичная документация доступна по `/api/swagger/` и `/api/redoc/`.
